# ERROR 404: Escape the System

Образовательный браузерный платформер о JavaScript с пятью секторами, **15 головоломками**, усложнённым паркуром и патрулирующими цифровыми монстрами. Цифровой исследователь и помощник PATCH восстанавливают повреждённую систему: по три исправления на сектор, каждое меняет настоящий игровой мир.

Проект написан на JavaScript ES Modules, Phaser **3.90.0**, Arcade Physics и Vite. Интерфейс на русском языке. React, TypeScript и сервер для игрового процесса не требуются. Облачный прогресс подключается через Supabase JavaScript SDK v2 и анонимную авторизацию.

## Сначала можно просто поиграть

Если у вас есть ссылка на размещённую игру, откройте её в браузере, нажмите «Играть» и задайте ник. Установка Node.js и создание базы для этого не нужны. На сайте есть [краткая инструкция](public/help.html) и кнопка скачивания полного проекта. Публичная игра не требует входа в ChatGPT; личный прогресс каждого игрока хранится отдельно.

Статус сохранения показывает, записаны ли результаты в облако или пока только в этот браузер. Фактическая публикация и проверки облака указаны в [TEST-REPORT.md](TEST-REPORT.md). Возможность облачного сохранения не означает, что запись уже подтверждена.

## Запуск исходников на своём компьютере

Нужен [Node.js](https://nodejs.org/) **22.12 или новее** с npm. Распакуйте архив, откройте терминал в папке `ERROR404` и выполните:

```sh
npm install
npm run dev
```

Откройте адрес, который Vite напечатает в терминале, обычно `http://localhost:5173`. Для остановки сервера нажмите `Ctrl+C`.

Без переменных окружения игра работает в явно обозначенном локальном демонстрационном режиме. PNG уже включены в проект; генерировать их перед первым запуском не нужно. Запуск двойным щелчком по `index.html` через `file://` не поддерживается: ES Modules и загрузке ресурсов нужен HTTP-сервер.

| Команда | Назначение |
| --- | --- |
| `npm install` | Установить зависимости по `package.json` и lock-файлу |
| `npm ci` | Установить точные версии из `package-lock.json` |
| `npm run dev` | Запустить сервер разработки |
| `npm run assets` | Воспроизводимо пересоздать процедурные PNG и спрайт-листы |
| `npm test` | Запустить тесты на встроенном `node:test` |
| `npm run build` | Создать production-сборку в `dist/` |
| `npm run preview` | Проверить собранную игру через локальный HTTP-сервер |

Чтобы проверить production-сборку:

```sh
npm run build
npm run preview
```

Для проверки на телефоне подключите его и компьютер к одной сети и используйте сетевой адрес, напечатанный Vite. Сетевой доступ может зависеть от настроек брандмауэра компьютера.

## Как играть

При первом запуске задайте ник длиной **2–16 символов**. Ник не обязан быть уникальным. Доступен первый уровень; следующий открывается после завершения предыдущего. В меню можно выбрать открытый уровень, посмотреть статистику и изменить настройки.

| Действие | Клавиши |
| --- | --- |
| Движение влево | `A` или `←` |
| Движение вправо | `D` или `→` |
| Прыжок | `W`, `Space` или `↑` |
| Терминал, рубильник, другое взаимодействие | `E` рядом с объектом |
| Пауза / закрыть терминал | `Esc` |
| Перезапустить уровень | `R` |

На сенсорном экране используйте кнопки движения, прыжка и взаимодействия. На телефоне удобнее играть горизонтально. Сообщение о повороте в вертикальной ориентации служит подсказкой. Полноэкранный режим доступен там, где его поддерживает браузер. Громкость, отключение звука и уменьшение эффектов находятся в настройках и сохраняются в браузере.

Подойдите к терминалу, нажмите `E`, прочитайте короткое объяснение и измените выделенное значение или оператор. Кнопка применения проверяет заранее определённый патч. Произвольный JavaScript не выполняется. Ошибка не делает уровень непроходимым: можно выбрать другое значение и повторить попытку.

В каждом секторе **три разных терминала**, в каждом терминале — две подсказки. Счётчик уровня суммирует ошибки и подсказки всех трёх заданий: от 0 до 6 подсказок за попытку. Для выхода нужно исправить все три узла, выполнить требования сектора и физически добраться до двери или портала. Терминалы встречаются на разных частях маршрута; исследуйте верхние площадки и боковые проходы.

### Опасности и перезапуск

- Падение, шипы и статические барьеры возвращают к активной контрольной точке. Исправления, предметы, таймер и счётчики этой попытки сохраняются.
- **Контакт с монстром перезапускает текущий сектор целиком.** После короткого экрана поражения персонаж возвращается к его началу; текущие исправления, предметы, контрольные точки и рубильник сбрасываются. Таймер, ошибки и подсказки начинают новую попытку. Заново пройти нужно этот сектор, а не всю игру.
- Ранее завершённые уровни, разблокировки, история и лучшие результаты остаются сохранёнными. Монстр не удаляет профиль.
- `R` также начинает текущий сектор заново. `Esc` открывает паузу; в паузе и редакторе физика и таймер остановлены.

Планируйте прыжки и наблюдайте за маршрутом патруля. В игре нет обязательного боя: задача — обойти опасность и восстановить код.

### Пять модулей

| Сектор | Три задания | Что меняется в мире |
| --- | --- | --- |
| 1. SYSTEM BOOT | Переменные, импульс прыжка, логические значения и `!` | Штатная скорость, усиленный прыжок, отключение лазера |
| 2. GRAVITY FAILURE | Гравитация, арифметика, скобки и среднее значение | Обычное притяжение, три опоры подъёмника, отключение поля |
| 3. ACCESS DENIED | Границы сравнения, индексы массива, логическое И | Дверь для двух ключей, проход к хранилищу, межсетевой экран |
| 4. INFINITE LOOP | Число повторений, шаг цикла, накопление `+=` | Три секции моста, четыре ступени, питание шлюза |
| 5. FINAL PATCH | Строгое равенство, отрицание и `&&`, составное условие | Охлаждение, безопасный реактор, стабилизация портала |

Уровни требуют исследования и точных прыжков. Время первого прохождения зависит от чтения объяснений, паркура и повторных попыток после встречи с монстрами; фиксированная длительность не гарантируется.

<details>
<summary>Решения головоломок — спойлеры</summary>

| Терминал | Исправление |
| --- | --- |
| 1 · Движение | `player.speed = 220;` |
| 1 · Прыжок | `player.jumpVelocity = -460;` |
| 1 · Лазер | `maintenanceMode = true`, тогда `laser.active = !maintenanceMode` даёт `false` |
| 2 · Гравитация | `world.gravity = 700;` |
| 2 · Подъёмник | `384 / 128` даёт три опоры |
| 2 · Стабилизатор | `(14 + 20) / 2` даёт среднее 17 |
| 3 · Доступ | `keys >= 2`; нужно собрать оба ключа |
| 3 · Маршрутизатор | `routes[1]` выбирает `"VAULT"` |
| 3 · Межсетевой экран | `verified && !quarantine` |
| 4 · Мост | `i < 3` создаёт три платформы |
| 4 · Лестница | `i < 4` и `i += 1` создают четыре ступени |
| 4 · Генератор | `energy += 2` в трёх повторениях даёт 6 |
| 5 · Охлаждение | `checksum === 404` |
| 5 · Реактор | `!overheated && energyReady` |
| 5 · Портал | `fuses >= 2 && leverOn`; нужны два предохранителя, рубильник и все исправления сектора |

</details>

### Звёзды и статистика

- **3 звезды:** 0 ошибок и 0 подсказок.
- **2 звезды:** не более 2 ошибок и не более 1 подсказки.
- **1 звезда:** остальные завершённые прохождения.

Правила применяются к **целой завершённой попытке сектора**: ошибки и подсказки складываются по трём терминалам. Время записывается отдельно и не создаёт скрытого штрафа к звёздам. Текущая попытка и история отделены от лучших показателей. Повторное прохождение не уменьшает максимум звёзд и не увеличивает минимальное время или минимальное число ошибок. Лучшие показатели могут относиться к разным попыткам.

## Подключение Supabase

Для локальной игры этот шаг необязателен. Для размещённой версии подготовлен отдельный Supabase-проект; работоспособность записи определяется статусом в игре и фактическими проверками в [TEST-REPORT.md](TEST-REPORT.md). Для независимой копии используйте собственный проект и шаги ниже. Без URL, публичного ключа, Anonymous Sign-Ins и настроенной базы приложение не может записывать результаты в облако.

1. Создайте проект в [Supabase](https://supabase.com/dashboard). Дождитесь его готовности.
2. Откройте **SQL Editor → New query**.
3. Скопируйте целиком [supabase/setup.sql](supabase/setup.sql) и выполните **Run**. Это объединённый установочный файл; отдельно повторять `schema.sql` и `policies.sql` после него не нужно.
4. В **Authentication → Sign In / Providers** включите **Anonymous Sign-Ins**. Названия пунктов могут немного отличаться в текущей версии панели. Если вы дополнительно включаете CAPTCHA, потребуется соответствующая настройка клиентского потока; базовая поставка использует обычный анонимный вход.
5. В настройках проекта найдите **Project URL** и публичный **publishable key** (`sb_publishable_...`). URL обычно имеет вид `https://ваш-проект.supabase.co`.
6. Создайте в корне проекта файл `.env`, скопировав `.env.example`, и заполните два поля:

```dotenv
VITE_SUPABASE_URL=https://ваш-проект.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=ваш-публичный-publishable-key
```

7. Перезапустите Vite. Переменные `VITE_*` читаются при запуске dev-сервера и встраиваются при production-сборке.
8. Запустите игру, задайте ник, завершите первый уровень и дождитесь статуса сохранения в облаке.
9. В **Authentication → Users** проверьте появление анонимного пользователя. В **Table Editor** проверьте таблицы `profiles`, `runs` и `level_progress`: профиль содержит ник, `runs` — завершённую попытку, `level_progress` — лучшие показатели уровня.
10. Обновите страницу и убедитесь, что ник, открытые уровни и статистика восстановились.

В браузер разрешено помещать только публичный ключ. **Не используйте `sb_secret_...`, `service_role`, пароль PostgreSQL и другие секреты** в `.env` с префиксом `VITE_`, JavaScript или настройках клиентской сборки. `.env` исключён из Git. Доступ к данным ограничивают политики RLS с `auth.uid()`, а не секретность публичного ключа.

Подробности SQL, политик и проверки двух пользователей: [supabase/README.md](supabase/README.md), [docs/SUPABASE-ACCEPTANCE.md](docs/SUPABASE-ACCEPTANCE.md). При обновлении базы предыдущей версии выполните [supabase/upgrade-three-puzzles.sql](supabase/upgrade-three-puzzles.sql) или весь обновлённый `setup.sql`: допустимое число подсказок в `runs` расширено с 0–2 до **0–6**. Обновление не требует удаления истории, профилей или рекордов.

### Локальное и облачное сохранение

Статус интерфейса различает «Прогресс сохранён локально», «Синхронизация...» и «Прогресс сохранён в облаке». Локальная запись не считается подтверждением записи в Supabase.

При отсутствии настроек Supabase или временной сетевой ошибке используется `localStorage`. Сетевые операции ограничены тайм-аутом 8 секунд. Синхронизация запускается при инициализации, сохранении, изменении ника и возвращении сети. Собственные ожидающие результаты отправляются с постоянными идентификаторами попыток: повторная отправка той же попытки не создаёт новую запись истории. Результат удаляется из очереди только после подтверждения истории и лучших показателей. Игра не делает запросы к БД из кадрового цикла.

Локальные гостевые результаты могут быть присоединены к первой созданной анонимной сессии. После привязки данные и очередь разделяются по UUID владельца: новая сессия не наследует очередь предыдущего облачного пользователя. Проверка ключа ожидает современный публичный ключ с префиксом `sb_publishable_`.

Анонимная сессия привязана к данным текущего браузера. Очистка данных сайта, приватный режим, другой браузер или устройство могут создать нового пользователя. Восстановление старой анонимной учётной записи и синхронизация между устройствами без дополнительной полноценной авторизации не обещаются. Если браузер запрещает постоянное локальное хранилище, локальные данные могут сохраняться только до закрытия страницы.

Результаты рассчитываются на клиенте. Этот учебный проект не предоставляет защищённый от читерства соревновательный рейтинг; для этого нужна серверная проверка игрового процесса.

## Публикация на Vercel

Исходники можно разместить независимо от предоставленной ссылки. Подготовлены `vercel.json`, Vite-сборка и `.env.example`. Публикация на вашем Vercel требует доступа к вашим GitHub и Vercel. Секретные ключи и токены в исходники не входят.

### 1. Загрузить исходники в GitHub

Создайте пустой репозиторий в GitHub, без автоматически добавленных файлов. В папке `ERROR404` выполните:

```sh
git init
git add .
git commit -m "Add ERROR 404 game"
git branch -M main
```

Затем добавьте remote, подставив настоящий URL своего репозитория, и отправьте код:

```sh
git remote add origin https://github.com/YOUR-ACCOUNT/error404.git
git push -u origin main
```

Если Git попросит авторизацию, используйте штатный вход GitHub или свой настроенный SSH-доступ. Не добавляйте токены в исходники.

### 2. Подключить репозиторий и переменные

1. В [Vercel](https://vercel.com/) выберите **Add New → Project**.
2. Подключите GitHub и импортируйте репозиторий.
3. Если `package.json` расположен во вложенной папке, укажите её как **Root Directory**.
4. Проверьте параметры:

| Параметр | Значение |
| --- | --- |
| Framework Preset | `Vite` |
| Install Command | `npm ci` |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Node.js | поддерживаемая Vercel версия 22.x или новее |

5. В **Environment Variables** добавьте `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`. Для тестовых Preview-развёртываний используйте отдельный Supabase-проект или осознанно выберите тот же.
6. Нажмите **Deploy**. После успешной сборки Vercel выдаст постоянный адрес вида `имя-проекта.vercel.app`.
7. Откройте адрес, пройдите уровень и проверьте появление записи в своей базе.

Для публикации локального демонстрационного режима переменные Supabase можно не задавать: статус будет сообщать о локальном сохранении. Добавление переменных позже требует **Redeploy**, потому что они встраиваются в статическую сборку.

### 3. Обновлять игру

После изменений запустите тесты и сборку, затем:

```sh
git add .
git commit -m "Update game"
git push
```

Vercel автоматически создаст новое развёртывание связанной ветки. Состояние и логи доступны во вкладке **Deployments**. После изменения только переменных среды выберите **Redeploy** в Vercel.

## Архитектура и ресурсы

| Папка | Содержимое |
| --- | --- |
| `src/scenes/` | Загрузка, меню, выбор уровня, Phaser-мир, результаты и финал |
| `src/core/` | Персонаж, построение уровней, терминалы, проверка патчей и Web Audio |
| `src/config/` | Конфигурация Phaser и карты пяти уровней в данных |
| `src/data/` | Учебные задания, объяснения и реплики PATCH |
| `src/ui/` | HTML-интерфейс поверх Canvas, редактор, настройки и статистика |
| `src/services/` | Supabase, анонимная сессия, прогресс и локальное хранилище |
| `src/utils/` | Проверка ввода, звёзды и форматирование времени |
| `public/assets/` | Готовые PNG: персонаж, PATCH, окружение, фоны, UI |
| `scripts/` | Генератор процедурной пиксельной графики |
| `supabase/` | SQL-схема, RLS и инструкция |
| `tests/` | Автоматические проверки игровой и сохранительной логики |
| `docs/` | Дополнительные инструкции и критерии приёмки |

Игровая физика, анимации, камера и столкновения работают в Phaser Arcade Physics. Редактор — безопасный интерфейс выбора из разрешённых патчей, без `eval()` и `new Function()`. Спрайты масштабируются без сглаживания. Процедурный генератор создаёт настоящие PNG и спрайт-листы с фиксированными кадрами. Обложка меню keyart.png создана генерацией изображений и уже включена в проект; запуск генератора её не перезаписывает. Звуки синтезируются Web Audio API; их воспроизведение начинается после действия пользователя.

## Проверка проекта

Воспроизведите основные автоматические проверки:

```sh
npm ci
npm run assets
npm test
npm run build
```

Затем запустите `npm run preview` и проверьте главное меню, движение и прыжки, все **15 терминалов**, ошибочные и правильные патчи, пять выходов и финал. Проверьте полный перезапуск сектора после монстра и сохранение прогресса завершённых уровней. Проверьте поворот экрана, экранные кнопки, паузу и обновление страницы после завершённого уровня. Для паркура и терминалов подготовлен [чек-лист игрового процесса](docs/PLAYTEST.md); для базы — [чек-лист приёмки Supabase](docs/SUPABASE-ACCEPTANCE.md).

Фактически выполненные проверки и ограничения среды перечислены в поставляемом отчёте `TEST-REPORT.md`, если он включён в архив. Успех локальных тестов сам по себе не подтверждает работу реального проекта Supabase, политик на сервере или публикацию на Vercel.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Ошибка установки или сборки | Версию Node.js, доступность npm; затем `npm ci` |
| Пустой экран при открытии файла | Запускайте через Vite, а не `file://`; посмотрите Console браузера |
| Нет звука | Нажмите кнопку в игре; проверьте громкость и mute в настройках и вкладке браузера |
| Сохранение только локально | URL и publishable key, Anonymous Sign-Ins, выполненный `setup.sql`, доступность сети |
| Ошибка `relation ... does not exist` | SQL выполнен в том же проекте, URL которого задан в `.env` |
| Ошибка RLS / permission denied | Применены схема и политики, текущая анонимная сессия имеет собственный профиль |
| Новые `.env` не подхватились | Перезапустите dev-сервер или пересоберите и повторно разверните production |
| После очистки сайта пропал прогресс | Очистка могла удалить локальные данные и ключ анонимной сессии |

## Состав поставки и оставшиеся действия

Архив содержит исходники, готовые PNG, генератор, `package-lock.json`, SQL и инструкции. Он доступен по кнопке на странице помощи и по адресу сайта `/downloads/ERROR404.zip`. `node_modules`, реальные `.env`, секретные ключи, токены и служебные временные файлы в исходный архив не входят. `.env.example` оставлен пустым для настройки независимой копии. Зависимости устанавливаются командой `npm install`.

Для игры по предоставленной ссылке достаточно браузера. Для локального запуска исходников — распаковать архив и выполнить две команды быстрого запуска. Для независимого облака — настроить свой Supabase, заполнить две переменные и выполнить SQL. Для собственного публичного URL — загрузить проект в GitHub и импортировать в Vercel. Эти действия не требуют изменения игрового кода. Оставшиеся действия именно для текущей поставки перечислены в [TEST-REPORT.md](TEST-REPORT.md).

Код и оригинальные ресурсы проекта распространяются по [MIT License](LICENSE). Сторонние библиотеки сохраняют собственные лицензии.

## Воспроизводимая проверка в браузере

В архив включены два дополнительных сценария Playwright. Они не нужны для обычной игры.

```bash
npx playwright install chromium
npm run dev -- --port 4173
```

Во втором терминале, в папке проекта:

```bash
npm run test:browser
npm run test:mobile
```

Если доступен системный Chromium в `/usr/bin/chromium`, сценарии используют его автоматически. Для другого пути задайте переменную `CHROMIUM_PATH`. Адрес сервера можно переопределить через `QA_URL` (по умолчанию `http://127.0.0.1:4173`). Отчёт и снимки сохраняются в `work/browser-qa`.

`test:browser` предназначен для проверки игрового процесса через клавиатуру и разрешённые поля редактора. Часть проверок может ускорять симуляцию Phaser; это не измерение FPS и не оценка времени прохождения человеком. Точный объём актуального сценария, результаты прохода новых карт и проверки всех 15 заданий смотрите в [TEST-REPORT.md](TEST-REPORT.md).

`test:mobile` проверяет экранные кнопки, исправление кода, паузу, настройки и переход в вертикальную ориентацию на эмулируемом телефоне. Физические Android/iOS-устройства и Safari отдельно не проверялись.

Фактически выполненные проверки и ограничения перечислены в [TEST-REPORT.md](TEST-REPORT.md).


## Облачная версия v2

Для опубликованной игры создан отдельный Supabase-проект ERROR404; таблицы, RLS и анонимный вход настроены. Реальные проверки двух игроков и браузерного SDK пройдены, детали в TEST-REPORT.md. Исходники в ZIP не содержат .env: независимая локальная копия запускается в локальном режиме, а для своего облака использует .env.example. Это позволяет изучать и публиковать свою копию без доступа к чужим сохранениям.
